## 🔧 발견된 관련 함수들

### 1. FUN_1000_0786: CGA 평면 변환 함수

**주소**: 1000:0786
**크기**: 435 bytes

**기능**: 16-way interleaved 데이터를 de-interleave

**핵심 알고리즘**:
```c
// 130회 또는 240회 루프
iVar1 = 0x82;  // 130
if (DAT_1988_0044 != 0x7800) {
    iVar1 = 0xf0;  // 240
}

do {
    // 64개 워드(128 bytes)를 출력
    // 16개 평면에서 각각 4개씩
    DAT_1988_0044[0] = puVar3[0];
    DAT_1988_0044[1] = puVar3[0x50];    // +80 워드
    DAT_1988_0044[2] = puVar3[0xa0];    // +160 워드
    DAT_1988_0044[3] = puVar3[0xf0];    // +240 워드
    DAT_1988_0044[4] = puVar3[0x140];   // +320 워드
    // ... 16개 평면 ...
    DAT_1988_0044[0xf] = puVar3[0x4b0]; // +1200 워드

    // 다음 4개 워드로 이동
    puVar4 = puVar3 + 4;
    iVar2 = iVar2 + 8;  // 8 bytes (4 워드) 처리

    // 160 bytes마다 큰 점프
    if (iVar2 == 0xa0) {  // 160
        iVar2 = 0;
        puVar4 = puVar3 + 0x4b4;  // +2408 bytes 점프
    }

    iVar1 = iVar1 - 1;
    puVar3 = puVar4;
} while (iVar1 != 0);
```

**평면 오프셋 패턴** (워드 단위):
```
0x000, 0x050, 0x0a0, 0x0f0,
0x140, 0x190, 0x1e0, 0x230,
0x280, 0x2d0, 0x320, 0x370,
0x3c0, 0x410, 0x460, 0x4b0
```

**총 데이터 크기**:
- 최대 오프셋: 0x4b0 = 1200 워드 = 2400 bytes
- 이것은 전체 화면 배경용 변환으로 추정
- 작은 스프라이트(237 bytes)는 이 포맷이 아님

### 2. FUN_1000_0cd1: 비트 재배열 함수

**주소**: 1000:0cd1
**크기**: 147 bytes

**기능**: 바이트 내 비트 순서 재배열

**알고리즘**:
```c
do {
    iVar2 = unaff_DI[1];
    iVar3 = *unaff_DI;

    // 4개 바이트(2개 워드)에서 각 비트 추출
    cVar4 = (char)iVar3;        // byte 0
    cVar5 = (char)(iVar3 >> 8); // byte 1
    cVar6 = (char)iVar2;        // byte 2
    cVar7 = (char)(iVar2 >> 8); // byte 3

    // 각 비트를 시프트하여 재배열
    // bit 7, 6, 5, 4, 3, 2, 1, 0 순으로 추출
    // 4개 바이트의 같은 위치 비트들을 모음

    in_CX = in_CX - 1;
} while (in_CX != 0);
```

**용도**: CGA bit-plane 재배열 (planar to chunky 변환?)

### 3. FUN_1000_2865: RLE 압축 해제 함수

**주소**: 1000:2865
**크기**: 47 bytes

**기능**: PackBits 스타일 RLE 압축 해제

**알고리즘**:
```c
iVar4 = 0x27;  // 39 바이트 처리
while (iVar4 >= 0) {
    iVar3 = *pcVar5++;  // 제어 바이트

    if (iVar3 == -0x80) {
        // 0x80: no-op
    }
    else if (iVar3 < 0) {
        // 음수: 반복 모드
        count = 1 - iVar3;  // 예: -1 -> 2회, -2 -> 3회
        byte = *pcVar5++;
        // byte를 count번 반복
    }
    else {
        // 0 이상: 리터럴 모드
        count = iVar3 + 1;  // 예: 0 -> 1바이트, 1 -> 2바이트
        // count 바이트 복사
    }

    iVar4 -= count;
}
```

**발견 사항**:
- 디컴파일된 코드에서 이 함수를 호출하는 곳을 찾지 못함
- 스프라이트 데이터에 RLE가 적용되지 않았을 가능성

### 4. FUN_1000_1e8a: LZW 압축 해제 래퍼

**주소**: 1000:1e8a
**크기**: 45 bytes

**기능**: LZW 압축 해제를 위한 설정 및 호출

```c
FUN_1000_1c1e();  // 준비
uVar1 = *(undefined2 *)0x320d;
uVar2 = *(undefined2 *)0x320f;
*(undefined2 *)0x320f = 0;
*(undefined2 *)0x320d = 0x2949;  // 출력 버퍼 주소
FUN_1000_1df2(uVar2, uVar1);     // 파라미터 설정
FUN_1000_5fe0();                 // LZW 압축 해제
FUN_1000_1c0c();                 // 정리
```

**메모리 주소**:
- 0x320d, 0x320f: 입력 버퍼 포인터
- 0x3213: 파일명 포인터?
- 0x2949: 출력 버퍼 (압축 해제된 데이터)

## 📊 현재 렌더링 시도 결과

### 테스트 PNG 생성

**파일**: `phase4_render_sprite.py`

**시도한 조합**:
- 폭: 32, 40, 48, 64, 80, 96, 128, 160 pixels
- 팔레트: CGA Palette 0 (Green/Red/Brown), Palette 1 (Cyan/Magenta/White)
- 총 48개 PNG 생성 (3 sprites × 8 widths × 2 palettes)

**렌더링 방법**:
```python
def render_sprite_simple(data, width=40, palette=CGA_PALETTE_1):
    pixels = []
    for byte in data:
        # 2 bits per pixel, MSB first
        for shift in [6, 4, 2, 0]:
            color_index = (byte >> shift) & 0x03
            pixels.append(palette[color_index])

    total_pixels = len(pixels)
    height = total_pixels // width
    img = Image.new('RGB', (width, height))
    img.putdata(pixels[:width * height])
    return img
```

**결과**:
- 모든 이미지가 노이즈처럼 보임
- 인식 가능한 스프라이트 형태 없음

**문제점**:
1. 바이트 순서가 인터리브되어 있을 가능성
2. 추가 변환 단계(FUN_1000_0786, FUN_1000_0cd1) 필요
3. 헤더 구조를 파악하지 못함
4. 스프라이트가 여러 프레임으로 구성되어 있을 가능성

## 📝 학습 내용

### CGA 그래픽 포맷 이해

**CGA Mode 4 (320x200, 4색)**:
- 2 bits per pixel (4가지 색상)
- 메모리: 0xB800:0000 (짝수 스캔라인), 0xBA00:0000 (홀수 스캔라인)
- 각 바이트 = 4 pixels
- 비트 순서: MSB first

**Planar vs Chunky**:
- Planar: 각 색상 비트가 분리된 평면에 저장
- Chunky: 픽셀 데이터가 연속으로 저장
- FUN_1000_0786, FUN_1000_0cd1은 planar → chunky 변환?

### 16-way Interleave 패턴

**발견**:
- 80 워드(160 bytes) 간격으로 16개 평면
- 총 1200 워드(2400 bytes) 스트라이드
- 이것은 특정 해상도/타일 크기에 대응

**계산**:
- 160 bytes = 640 pixels (2bpp)
- 640 pixels / 16 평면 = 40 pixels/평면
- 40 pixels 폭의 타일?
