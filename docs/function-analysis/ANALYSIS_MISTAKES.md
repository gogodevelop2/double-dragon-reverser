## ❌ 했던 실수들

### 1. 자동화부터 시도 (가장 큰 실수!)

**실수**:
처음부터 복잡한 pyghidra 스크립트를 작성하여 자동으로 모든 함수를 찾으려 함

- 근본 원인 파악 못 함

**올바른 접근**:
- 먼저 **수동으로 하나씩 확인**
- 디컴파일된 코드 직접 읽기
- 단순한 hexdump부터 시작
- 이해한 후에 자동화

**교훈**:
> "잘 모를 때는 자동화 돌리지 말고 다시 앞으로 돌아가서 하나씩 추적하기" - 사용자 조언

### 2. 세그먼트 주소 계산 혼동

**실수 #1**: 파일 오프셋 vs 메모리 주소 혼동
```bash
# ❌ 잘못된 시도
xxd -s 0x18da DDMAIN.EXE  # 파일 오프셋으로 착각
```

**문제**:
- Ghidra 주소는 **런타임 메모리 주소**
- .EXE 파일의 **물리 오프셋이 아님**

**실수 #2**: 코드 vs 데이터 세그먼트 혼동
```python
# ❌ 처음엔 1000:18da로 생각
addr = (0x1000 << 4) + 0x18da
```

**올바른 이해**:
- **코드 세그먼트**: `0x1000` (함수들)
- **데이터 세그먼트**: `0x1988` (변수, 테이블)
- `0x18da`는 데이터 세그먼트 기준

---

### 3. FAR pointer vs NEAR pointer 혼동

**실수**:
4바이트 FAR pointer (segment:offset)일 거라 추측하고 스크립트 작성

```python
# ❌ 잘못된 가정
for i in range(11):
    addr = base + (i * 4)  # 4바이트씩
    offset = read_word(addr)
    segment = read_word(addr + 2)
```

**확인 방법**:
- FUN_1000_0db2 코드 보니 `undefined2 *` (2바이트 포인터)
- `iVar3 = 0xb` (11회) 루프에서 `puVar5++` (포인터 증가)
- `undefined2 *`이면 2바이트씩 증가

**올바른 이해**:
- **NEAR pointer**: 2바이트 (같은 세그먼트 내 오프셋)
- 11개 × 2 bytes = 22 bytes

**교훈**:
먼저 **디컴파일 코드를 읽고** 데이터 타입 확인하기!

---

### 4. Ghidra API 오용

**실수 #1**: `getFunctionAt()` 결과만 신뢰
```python
# ❌ 이것만 체크
func = flat_api.getFunctionAt(addr)
if not func:
    print("UNKNOWN")  # 너무 성급한 결론
```

**놓친 것**:
- `getFunctionContaining()` - 함수 내부 레이블일 수 있음
- `getInstructionAt()` - 코드인지 확인
- `getDataAt()` - 데이터로 분류되었는지 확인

**실수 #2**: 에러 메시지 무시
```python
# Ghidra 경고를 무시함
# "WARNING: Could not recover jumptable"
# "WARNING: Treating indirect jump as call"
```

**의미**:
- Ghidra가 간접 점프 테이블을 분석 못 함
- **이게 핵심 힌트였음!**

---

### 5. 결과 해석 오류

**실수**: "UNKNOWN"이 나오자 바로 "함수가 없다"고 결론

**실제 의미**:
1. Ghidra가 **함수로 인식 안 함** (분석 실패)
2. 또는 **데이터로 분류**
3. 또는 **도달 불가능한 코드**로 판단

**올바른 접근**:
1. 왜 Ghidra가 인식 못 했는지 원인 파악
2. 수동으로 해당 주소 확인
3. 어셈블리 코드 직접 보기

2. **데이터 타입 확인**

### Phase 2: 데이터 확인

## 🎯 핵심 교훈

### 1. 순서가 중요하다

```
❌ 자동화 → 실패 → 원인 모름 → 더 복잡한 자동화 → 미궁

✅ 수동 추적 → 이해 → 패턴 발견 → (필요시) 자동화
```

### 2. 코드를 먼저 읽어라

**pyghidra 스크립트 쓰기 전에**:
- 디컴파일된 C 코드 읽기
- 주석 확인
- 변수 타입 확인
- 호출 관계 파악

### 3. 간단한 것부터 시작

**복잡한 분석 도구 대신**:
- `hexdump`
- `ls` (파일 존재 확인)
- 간단한 바이트 읽기 스크립트
- 수동 계산

### 4. 에러 메시지를 주의깊게 읽어라

```c

```

이게 **핵심 힌트**였음!

### 5. 결과를 성급하게 해석하지 마라

- "UNKNOWN" ≠ "함수가 없다"
