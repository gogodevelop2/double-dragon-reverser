## 🎯 주요 발견사항

### 1. 함수 포인터 디스패처 시스템 ⭐⭐⭐

**가장 중요한 발견**: Double Dragon은 11개 엔트리의 **함수 포인터 테이블**을 사용하여 동적 디스패치를 구현합니다.

**핵심 함수**:
- **FUN_1000_0db2**: 테이블 초기화 (0x18da 또는 0x18f0 → 0x18c4로 11개 워드 복사)
- **FUN_1000_48e0**: 스프라이트 렌더링 디스패처 (0x18c6)
- **FUN_1000_599d**: 화면 업데이트 디스패처 (0x18d8)
- **FUN_1000_8135**: 객체 상태 디스패처 (0x18d0)

**테이블 구조**:
```
Mode 1 소스: 0x18da (11 words)
Mode 2 소스: 0x18f0 (11 words)
         ↓ 복사
활성 테이블: 0x18c4 ~ 0x18d8 (11 words)
```

**의미**:
- 1980년대 C 코드에서 OOP의 가상 함수(vtable) 구현
- 게임 모드별로 다른 함수 세트 사용 가능
- 런타임에 동적으로 함수 변경 가능

**문서**: [FUNCTION_POINTERS.md](FUNCTION_POINTERS.md)

---

### 2. 스프라이트 로딩 파이프라인 ⭐⭐⭐

**완전히 이해함**: FUN_1000_0b94가 4개 스프라이트를 로딩하는 전체 과정

**파이프라인**:
```
1. LZW 압축 해제 × 4 (FUN_1000_1e8a)
   LINDA.EG1 → 0x2f9e (237 B)
   ABOBO.EG1 → 0x3f9e (508 B)
   PLAYER1.EG1 → 0x493a (2711 B)
   WEAPONS.EG1 → 0x53a0 (980 B)

2. CGA Planar → Chunky 변환 × 4 (FUN_1000_0cd1) ✅ 구현 완료
   4 planar bytes → 8 pixels (4-bit each)

3. 팔레트 생성 @ 0x8800 (256 bytes)
   palette[i] = ~((i & 0xF ? 0xF : 0) | (i & 0xF0 ? 0xF0 : 0))

4. 팔레트 변환 × 7 (FUN_1000_0d64) ⏳ 미구현
   16-byte 룩업 테이블 위치 불명

5. 스프라이트 주소 테이블 설정 @ 0xf4f0
   12개 워드 (프레임 포인터)
```

**구현 완료**:
- `cga_planar_to_chunky.c`: CGA 비트 재배열 ✅
- `dd_lzw_decompress`: LZW 압축 해제 ✅

**미완성**:
- FUN_1000_0d64 팔레트 변환 (룩업 테이블 찾기)
- 스프라이트 파일 구조 (헤더, 프레임 메타데이터)

**문서**:
- [functions/FUN_1000_0b94.md](functions/FUN_1000_0b94.md)

### 3. 렌더링 체인 추적 ⭐⭐

**메인 루프 → 렌더링**:
```
entry → 메인 루프
│
├─ FUN_1000_0360() - 객체 루프 (0x16c6 ~ 0x176e, 0x18 간격)
│  ├─ FUN_1000_0412() - 객체 업데이트
│  ├─ FUN_1000_0e30() - 상태별 함수 디스패치
│  ├─ FUN_1000_3e6d() - 상태 관리
│  │  └─ FUN_1000_3f71() - 위치 계산
│  │     └─ FUN_1000_12c0() ❌ 미발견! (BLIT 함수)
│  └─ FUN_1000_041b() - 정리
│
├─ FUN_1000_211b() - 렌더링 준비
│  └─ FUN_1000_20a0() ⭐ 새 발견!
│     └─ piVar2[5] = *(int *)0xf4f0  (스프라이트 주소 테이블 사용)
│
├─ FUN_1000_029a() - 스프라이트 처리
│  └─ FUN_1000_48e0() - 렌더링 디스패처 (0x18c6)
│
└─ FUN_1000_3830() - 메인 게임 로직
   └─ FUN_1000_599d() × 2 - 화면 플립 (0x18d8)
      └─ VGA 수직 블랭킹 대기 (in(0x3da))
```

**발견**:
- FUN_1000_20a0: 스프라이트 주소 테이블(0xf4f0) 사용
- FUN_1000_599d: 더블 버퍼링 (2번 호출 + VGA 동기화)
- FUN_1000_12c0: 여전히 미발견 (디컴파일 실패?)

### 4. VGA 더블 버퍼링 ⭐⭐

**패턴 발견** (FUN_1000_3830에서):
```c
// 백버퍼에 모든 스프라이트 그리기 완료

FUN_1000_599d();  // 페이지 플립 준비
FUN_1000_599d();  // 실제 플립?

// VGA 수직 블랭킹 대기
do {
  vga_status = in(0x3da);  // VGA 상태 레지스터
} while ((vga_status & 8) == 0);  // bit 3 = Vertical Retrace

// 이제 백버퍼가 화면에 표시됨 (티어링 없음!)
```

**CGA Mode 4 메모리**:
- 페이지 0: 0xB8000 (16 KB)
- 페이지 1: 0xBC000 (16 KB)
- 포트 0x3D8 bit 3로 전환

## 💡 주요 인사이트

### 1. 코드 품질
- **체계적**: 함수 포인터 테이블로 깔끔한 아키텍처
- **효율적**: In-place 변환, 더블 버퍼링, VGA 동기화
- **모듈화**: Mode별 다른 함수 세트

### 2. 역공학 전략
- **실행 경로 추적**: entry → 메인 루프 → 각 함수 (작업 원칙 준수)
- **패턴 인식**: 함수 포인터 디스패처 패턴 발견 → 전체 시스템 이해
- **문서화**: 각 발견 즉시 기록 → 퍼즐 조각 맞추기

### 3. 30년 전 프로그래밍
- **제약 속 창의성**: 64KB 코드, 16KB VRAM → 효율적 설계
- **OOP in C**: vtable 패턴을 C로 구현
- **하드웨어 직접 제어**: VGA 포트, 타이밍 동기화
