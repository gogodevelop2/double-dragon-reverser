## 🔍 주요 발견사항

### 1. 함수 포인터는 2바이트 (Near Pointer)

```python
# 1988:18da에서 22 bytes 읽기
0x5f07, 0x5e55, 0x8492, 0x84ee, 0x8583, 0x853d,
0x8622, 0x7eb0, 0x5aaa, 0x5b5f, 0x5c0a
```

- **FAR pointer (segment:offset)가 아님**
- **NEAR pointer (offset만)**: 코드 세그먼트 1000: 기준
- 각 엔트리 2 bytes, 총 11개 = 22 bytes

### 2. 타겟 주소들이 Ghidra 인식 함수가 아님 ⭐⭐⭐

**문제점**:
모든 11개 주소가 디컴파일된 함수 목록에 **없음**

**예시**:
- `1000:5e55` → `FUN_1000_5e55.c` 파일 없음
- 주변 함수: `FUN_1000_583b`, `FUN_1000_5860`
- 간격이 너무 커서 함수 내부도 아님

**가능한 원인**:
1. ❌ **Ghidra 분석 실패**: 해당 주소를 코드로 인식하지 못함
2. ❌ **데이터 영역**: 함수가 아니라 데이터 테이블
3. ⭐ **동적 코드 생성**: 런타임에 생성되는 코드?
4. ⭐ **Overlay 또는 Bank Switching**: 메모리 뱅크 교환?

## 💡 FUN_1000_0db2 동작 분석

```c
void FUN_1000_0db2(void) {
    if (DAT_1988_0035 != 0) {  // Mode 0이 아니면
        undefined2 *source;
        if (DAT_1988_0035 == 0x01) {
            source = (undefined2 *)0x18da;  // Mode 1
        } else {
            source = (undefined2 *)0x18f0;  // Mode 2
        }

        undefined2 *dest = (undefined2 *)0x18c4;

        // 11개 워드 복사
        for (int i = 11; i > 0; i--) {
            *dest++ = *source++;
        }
    }
}
```

**동작**:
1. 현재 모드 확인 (`DAT_1988_0035`)
2. Mode 1이면 `1988:18da`, Mode 2이면 `1988:18f0`에서
3. `1988:18c4`로 22 bytes 복사
4. 이후 디스패처 함수들이 `1988:18c4` 테이블 사용

## 🎯 디스패처 함수 동작

### 예시: FUN_1000_48e0

```c
void FUN_1000_48e0(void) {
    /* WARNING: Could not recover jumptable at 0x000148e0. Too many branches */
    /* WARNING: Treating indirect jump as call */
    (*(code *)*(undefined2 *)0x18c6)();
}
```

**실행 흐름**:
1. `DS:0x18c6` (= `1988:18c6`) 주소에서 2바이트 읽기
2. 읽은 값: **0x5e55**
3. `CS:0x5e55` (= `1000:5e55`)로 점프
4. **문제**: `1000:5e55`에 함수가 없음!

## ❓ 미해결 문제

### 1. 왜 타겟 주소에 함수가 없는가?

**가능한 시나리오**:

#### A. Ghidra 분석 불완전
- Ghidra가 일부 코드 영역을 데이터로 잘못 분류
- 재분석 필요?

#### B. 동적 코드 패칭
- 게임 시작 시 메모리에 코드를 복사/생성
- Double Dragon은 복사 보호나 압축 해제가 있을 수 있음

#### C. Overlay 시스템
- DOS 시대에는 메모리 절약을 위해 코드를 교체하는 overlay 기법 사용
- 동일한 주소에 다른 코드가 로드될 수 있음

#### D. Bank Switching
- EGA/VGA 메모리 뱅크처럼 코드 뱅크를 전환?
- 0x5e55 주소가 여러 뱅크에 존재?

### 2. Mode 1 vs Mode 2 차이

모든 11개 함수 주소가 다름:

**추정**:
- Mode 1: CGA Mode 4 (320x200, 4색) 전용 렌더링 함수?
- Mode 2: EGA/Tandy 그래픽 모드 함수?
- 또는 1P/2P 모드 차이?

### 3. 실제 함수 찾기

**방법**:
1. DOSBox 디버거로 런타임 추적
   ```
   bp 1000:48e0
   g
   # 브레이크 시 1988:18c6 값 확인
   # 점프 대상 1000:xxxx 확인
   ```

2. Ghidra 수동 디스어셈블
   - 주소 1000:5e55로 이동
   - 강제로 코드로 변환 (D → C)
   - 함수 생성 (F)

3. 바이너리 직접 확인
   - 해당 오프셋의 기계어 확인
   - 수동 디스어셈블

## 📚 참고: DOS 코드 세그먼트 주소 계산

### 세그먼트:오프셋 → 물리 주소

```
Physical = (Segment << 4) + Offset
```

**예시**:
```
1000:5e55 → (0x1000 << 4) + 0x5e55
          → 0x10000 + 0x5e55
          → 0x15e55
```

### Ghidra 주소 vs 파일 오프셋

- **Ghidra 주소**: 런타임 메모리 주소
- **파일 오프셋**: DOS .EXE 파일 내 위치
- 변환 필요: EXE 헤더 고려
