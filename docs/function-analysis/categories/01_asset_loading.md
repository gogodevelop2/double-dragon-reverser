## 🎨 변환 알고리즘

### 1. CGA Planar to Chunky (FUN_1000_0cd1)

**구현 상태**: ✅ **완료**

**입력**: 4 bytes (4 planar planes)
```
Plane 0: b7 b6 b5 b4 b3 b2 b1 b0
Plane 1: b7 b6 b5 b4 b3 b2 b1 b0
Plane 2: b7 b6 b5 b4 b3 b2 b1 b0
Plane 3: b7 b6 b5 b4 b3 b2 b1 b0
```

**출력**: 4 bytes (8 pixels, 4-bit each)
```
Pixel 0: P0[7] P1[7] P2[7] P3[7]  (4 bits)
Pixel 1: P0[6] P1[6] P2[6] P3[6]
...
Pixel 7: P0[0] P1[0] P2[0] P3[0]
```

**파일**: `cga_planar_to_chunky.c`

### 2. 팔레트 생성

**위치**: 0x8800 (256 bytes)

**알고리즘**:
```c
for (int i = 0; i < 256; i++) {
    byte val = 0;
    if (i & 0x0F) val |= 0x0F;    // 하위 4비트
    if (i & 0xF0) val |= 0xF0;    // 상위 4비트
    palette[i] = ~val;             // 반전
}
```

**결과**:
```
0x00 → 0xFF
0x01 → 0xF0
0x10 → 0x0F
0xFF → 0x00
```

### 3. 팔레트 변환 (FUN_1000_0d64)

**구현 상태**: ❌ **미완성**

**알고리즘**:
```c
for (int i = 0; i < 256; i++) {
    byte upper = lookup[(i >> 4) & 0xF];
    byte lower = lookup[i & 0xF];
    output[i] = (upper << 4) | lower;
}
```

**문제**: 16 bytes 룩업 테이블 위치 불명 (in_BX)

### 4. 16-plane De-interleave (FUN_1000_0786)

**용도**: 배경 이미지 (*.PC1 파일)

**알고리즘**:
- 16개 평면이 80워드(160 bytes) 간격으로 인터리브
- 2400 bytes 단위 스트라이드
- 130회 또는 240회 루프

**스프라이트에는 적용 안 됨** (파일 크기가 작음)

## 🔍 핵심 발견 사항

### LZW 압축

**Unix compress 호환**:
- 헤더: 0x1F 0x9D
- MSB-first 비트 순서
- Code 256 = 비트 크기 증가 (9→10→11→...)
- 최대 16 bits

**구현**:
- `dd_lzw_decompress` (C) ✅ 완료
- LINDA.EG1 (7773 B) → 237 B 성공

### 스프라이트 주소 테이블

**위치**: 0xf4f0 (12개 워드)

```
0xf4f0: 0x8100, 0x8100, 0x8100, 0x8100, 0x8100
0xf4fa: 0x8200, 0x8700, 0x8700, 0x8700
0xf502: 0x8400, 0x8500, 0x8300
```

**추정**: 12개 스프라이트 프레임 포인터

### 파일 구조 미상

**문제점**:
1. 첫 바이트 (0x3D, 0x7F, 0xC8)의 의미
2. 헤더 크기
3. 프레임 메타데이터 (폭, 높이, 오프셋)
4. 여러 프레임 혼재 여부

**다음 단계**:
