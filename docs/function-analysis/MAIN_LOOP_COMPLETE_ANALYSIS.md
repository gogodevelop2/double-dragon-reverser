## 🎯 핵심 함수 상세 분석

### FUN_1000_3830 - 메인 게임 로직

**주소**: 1000:3830
**크기**: 447 bytes
**복잡도**: 매우 높음

#### 주요 기능

1. **게임 상태 관리**
   - 플레이어 생존 체크
   - 레벨 전환 처리
   - 게임 오버 처리

2. **재귀 호출 구조**
   - LAB_1000_024b에서 자기 자신을 호출
   - 상태 머신 패턴

3. **VGA 동기화**
   ```c
   do {
     bVar1 = in(0x3da);  // VGA 상태 레지스터
   } while ((bVar1 & 8) == 0);  // 수직 블랭킹 대기
   ```

#### 메모리 맵

| 주소 | 크기 | 용도 | 값 |
|------|------|------|-----|
| 0x16c8 | 1 byte | 플레이어1 상태 | 0=죽음, 0x2a=살아있음 |
| 0x16e0 | 1 byte | 플레이어2 상태 | 0=죽음, 0x2a=살아있음 |
| 0x38d0 | 1 byte | 레벨 전환 카운터 | 0~6 |
| 0x38d1 | 1 byte | 게임 상태 플래그 | 0 또는 1 |
| 0x38d3 | 2 bytes | 특수 상태 | 999=레벨전환 |
| 0x318a | 2 bytes | 프레임 타이밍 | 0~15 |
| 0x318e | 1 byte | 게임 종료 플래그 | 0=종료 |
| 0x16b0 | 2 bytes | 전체 프레임 카운터 | 증가 |

#### 상태 전환 다이어그램

```
┌──────────────┐
│ 일반 게임    │ ← *(int *)0x38d3 != 999
│              │   → FUN_1000_39ee()
└──────┬───────┘
       │
       │ *(int *)0x38d3 == 999
       ▼
┌──────────────┐
│ 레벨 전환    │
│ 카운터: 0→6  │
└──────┬───────┘
       │
       │ 카운터 == 6
       ▼
┌──────────────┐     플레이어 죽음
│ 플레이어     │ ──────────────→ [게임 오버]
│ 생존 체크    │
└──────┬───────┘
       │
       │ 살아있음
       ▼
┌──────────────┐
│ 플레이어     │
│ 초기화       │
│ VGA 동기화   │
└──────┬───────┘
       │
       └─→ LAB_1000_024b (메인 루프)
```

## 🔑 함수 포인터 디스패처

### 1. FUN_1000_16e0 - 객체 타입별 업데이트

```c
(*(code *)*(undefined2 *)(*(byte *)0x168f + 0x16ef))();
```

- **인덱스**: `0x168f` (객체 타입)
- **테이블**: `0x16ef`
- **용도**: 플레이어/적/무기별 다른 업데이트 로직

### 2. FUN_1000_0e30 - 객체 상태별 행동

```c
(*(code *)*(undefined2 *)(*(byte *)0x1691 + 0xe3f))();
```

- **인덱스**: `0x1691` (객체 상태)
- **테이블**: `0xe3f`
- **용도**: Idle/Walk/Attack/Jump 등 상태별 행동

### 3. FUN_1000_8135 - 메인 루프 디스패처

```c
(*(code *)*(undefined2 *)0x18d0)();
```

- **주소**: `0x18d0` (고정)
- **용도**: 메인 루프에서 매 프레임 호출
- **참고**: docs/function-analysis/FUNCTION_POINTERS.md
