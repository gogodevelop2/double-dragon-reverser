## 💡 핵심 발견

### 1. 인덱스 계산식

```c
index = (direction * 7) + type;
```

**방향 값** (0x3532):
- 0, 1, 2, 3, 4, 5, 6, 7
- 8방향? (또는 상태별)

**타입 값** (0x3530):
- 0 ~ 6 (7가지)
- 배열2 객체 종류

**테이블 크기**: 8 × 7 = 56 엔트리

### 2. 2개 스프라이트 테이블

| 주소 | 용도 | 선택 조건 |
|------|------|----------|
| **0x2c40** | 기본 테이블 | 방향 ≤ 5 또는 조건 미충족 |
| **0x2c78** | 대체 테이블 | 방향 > 5 + (조건 A 또는 B) |

**조건 A**:
```c
(*(int *)0x3540 == -1) && (*(int *)0x353a == -1)
```

**조건 B**:
```c
(*(int *)0x3540 != -1) && (*(byte *)(*(int *)0x3540 + 4) & 2)
```

→ 0x3540이 포인터이고, +4 오프셋의 bit 1이 플래그

### 3. 테이블 레이아웃

```
0x2c40:
  [방향 0, 타입 0] → 스프라이트 포인터
  [방향 0, 타입 1] → 스프라이트 포인터
  ...
  [방향 0, 타입 6] → 스프라이트 포인터
  [방향 1, 타입 0] → 스프라이트 포인터
  ...
  [방향 7, 타입 6] → 스프라이트 포인터

0x2c78:
  (동일 구조, 다른 스프라이트)
```

**총 56 × 2 = 112개 포인터** (각 2 bytes)

### 4. 배열1 vs 배열2 비교

| 항목 | 배열1 (FUN_1000_04a9) | 배열2 (FUN_1000_220b) |
|------|---------------------|---------------------|
| **타입 주소** | 0x168f | 0x3530 |
| **방향 주소** | 0x1690 | 0x3532 |
| **포인터 출력** | 0x1695 | 0x3534 |
| **테이블 1** | 0x2f9e | 0x2c40 |
| **테이블 2** | 0x3f9e | 0x2c78 |
| **인덱스 계산** | direction × 10 + type | direction × 7 + type |
| **타입 개수** | 10개 | 7개 |

**차이점**:
- 배열1: 10가지 타입 (캐릭터)
- 배열2: 7가지 타입 (투사체/아이템)

### 1. 테이블 데이터 추출

**원작**: 바이너리 내장 테이블
- 0x2c40 ~ 0x2c6f (112 bytes)
- 0x2c78 ~ 0x2ca7 (112 bytes)

**추출 방법**:
```python
# pyghidra로 메모리 덤프
memory = program.getMemory()
addr_2c40 = address_space.getAddress(0x1000 << 4 + 0x2c40)

table_2c40 = []
for i in range(56):
    addr = addr_2c40.add(i * 2)
    low = memory.getByte(addr) & 0xFF
    high = memory.getByte(addr.add(1)) & 0xFF
    ptr = (high << 8) | low
    table_2c40.append(ptr)
```

**개선**:

```cpp
bool should_use_alt_table(const Object* obj) {
    if (obj->direction <= Direction::Dir5) {
        return false;
    }

    // 조건 A
    if (obj->flag_b_ptr == nullptr &&
        obj->flag_a == -1) {
        return true;
    }

    // 조건 B
    if (obj->flag_b_ptr != nullptr) {
        uint8_t flags = *(uint8_t*)(obj->flag_b_ptr + 2);
        return (flags & 0x02) != 0;
    }

    return false;
}
```

### 3. 타입 안전성

**원작**: 바이트 곱셈
```c
index = (char)(direction * 7 + type);  // overflow 가능
```

**현대**: enum class + 범위 체크
```cpp
int calculate_index(Direction dir, ObjectType type) {
    int d = static_cast<int>(dir);
    int t = static_cast<int>(type);

    assert(d < 8 && t < 7);
    return d * 7 + t;
}
```

### 4. 테이블 주소 지정 vs 배열 인덱스

**원작**: 주소 계산
```c
table = (uint16_t *)(index + 0x2c40);  // 주소 = 베이스 + 오프셋
ptr = *table;
```

→ 인덱스가 곧 바이트 오프셋 (word 단위 아님!)
→ 실제로는 `index * 2`가 필요하지만 주소 계산에서 자동 처리됨

**현대**: 배열 인덱스
```cpp
int16_t* table = sprite_table_0x2c40;
int16_t ptr = table[index];  // 컴파일러가 × 2 처리
```
