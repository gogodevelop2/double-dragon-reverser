# Double Dragon 함수 포인터 시스템

**생성일**: 2025-11-24

---

## 📋 개요

Double Dragon은 **함수 포인터 테이블**을 사용하여 게임 상태와 객체 타입에 따라 동적으로 함수를 호출합니다. 이것은 1980년대 C 코드에서 객체지향 프로그래밍(OOP)의 **다형성(polymorphism)**을 구현하는 전형적인 패턴입니다.

## 🔧 초기화 (FUN_1000_0db2)

### 호출 경로

```
entry (1000:0000)
└─ [Mode 1 선택]
   └─ FUN_1000_0660() - Mode 1 초기화
      ├─ FUN_1000_1e8a() - LZW 압축 해제
      ├─ FUN_1000_0b94() - 스프라이트 로딩
      ├─ FUN_1000_0db2() ⭐ 함수 포인터 테이블 초기화
      ├─ DAT_1988_0042 = 9
      └─ FUN_1000_0dd6()
```

### 코드 분석

```c
void FUN_1000_0db2(void) {
  if (DAT_1988_0035 != 0) {  // Mode 0이 아니면

    // 소스 테이블 선택
    undefined2 *source;
    if (DAT_1988_0035 == 0x01) {
      source = (undefined2 *)0x18da;  // Mode 1
    } else {
      source = (undefined2 *)0x18f0;  // Mode 2
    }

    // 활성 테이블로 복사 (11개 워드)
    undefined2 *dest = (undefined2 *)0x18c4;
    for (int i = 11; i > 0; i--) {
      *dest++ = *source++;
    }
  }
}
```

**작동 원리**:
1. 현재 게임 모드(`DAT_1988_0035`) 확인
2. Mode 1이면 0x18da, Mode 2이면 0x18f0에서
3. 11개 함수 주소를 0x18c4로 복사
4. 이후 모든 디스패처는 0x18c4 테이블 사용

## 🔍 상세 분석 - 핵심 디스패처

### 1. FUN_1000_48e0 (인덱스 1) - 스프라이트 렌더링

```c
void FUN_1000_48e0(void) {
  (*(code *)*(undefined2 *)0x18c6)();
}
```

**호출 맥락** (FUN_1000_029a에서):
```c
DAT_1988_4664 = sprite_address;  // 스프라이트 주소 설정
FUN_1000_48e0();                 // 렌더링 함수 호출
```

**용도**:
- 스프라이트 타입별로 다른 렌더링 함수 호출
- LINDA, ABOBO, PLAYER1, WEAPONS 등 각각 다른 처리 가능

**문서**: [FUN_1000_48e0.md](functions/FUN_1000_48e0.md)

### 2. FUN_1000_8135 (인덱스 6) - 객체 상태 처리

이 함수는 다른 패턴을 사용합니다:

```c
void FUN_1000_8135(void) {
  (*(code *)*(undefined2 *)0x18d0)();
}
```

**추가로 FUN_1000_0e30에서**:
```c
void FUN_1000_0e30(void) {
  (*(code *)*(undefined2 *)(*(byte *)0x1691 + 0xe3f))();
}
```

이것은 **이중 간접 참조** (double indirection):
- `*(byte *)0x1691`: 객체 타입 또는 상태 값 읽기
- `+ 0xe3f`: 오프셋 추가하여 테이블 인덱스 계산
- `*(undefined2 *)`: 해당 위치의 함수 주소 읽기
- `(code *)`: 함수 포인터로 캐스팅
- `()`: 호출

**용도**: 플레이어/적 객체의 상태(idle, walk, attack 등)별로 다른 함수 호출

### 3. FUN_1000_599d (인덱스 10) - 화면 업데이트

```c
void FUN_1000_599d(void) {
  (*(code *)*(undefined2 *)0x18d8)();

```

**호출 맥락** (FUN_1000_3830에서):
```c
// 프레임 준비
FUN_1000_599d();  // 첫 번째 호출
FUN_1000_599d();  // 두 번째 호출 (더블 버퍼?)

// VGA 수직 블랭킹 대기
do {
  vga_status = in(0x3da);
} while ((vga_status & 8) == 0);

// 화면 갱신 완료
```

**용도**:
- VGA 페이지 플리핑 (더블 버퍼링)
- 백버퍼 → 프론트버퍼 전환
- 티어링(tearing) 방지

**문서**: [FUN_1000_599d.md](functions/FUN_1000_599d.md)

## 💡 OOP 패턴 비교

### 현대 C++의 가상 함수

```cpp
class Sprite {
public:
  virtual void render() = 0;
};

class PlayerSprite : public Sprite {
  void render() override { /* ... */ }
};

class EnemySprite : public Sprite {
  void render() override { /* ... */ }
};

// 사용
Sprite* sprite = getSprite();
sprite->render();  // 동적 디스패치
```

### Double Dragon의 C 구현

```c
// 함수 포인터 타입
typedef void (*RenderFunc)(void);

// 함수 포인터 테이블 (vtable과 유사)
uint16_t function_table[11];

// 초기화
void init_function_table_mode1() {
  function_table[1] = (uint16_t)&render_sprite_cga;
  function_table[10] = (uint16_t)&flip_vga_page;
  // ...
}

// 디스패치
void dispatch_render() {
  RenderFunc func = (RenderFunc)function_table[1];
  func();
}
```

**장점**:
- 메모리 효율적 (vtable 하나만)
- 런타임에 동적으로 함수 변경 가능
- 게임 모드별로 다른 테이블 사용

**단점**:
- 타입 안전성 없음
- 디버깅 어려움
- Ghidra가 "Too many branches" 경고

## 🔬 실제 함수 주소 찾기

### 방법 1: Ghidra에서 데이터 섹션 확인

1. Ghidra에서 주소 0x18da로 이동
2. 데이터 타입을 "pointer" (2 bytes)로 설정
3. 11개 엔트리 확인
4. 각 포인터가 가리키는 함수 확인

### 방법 2: DOSBox 디버거

```
> bp 1988:0db2          # FUN_1000_0db2 진입점
> g                      # 실행
# 브레이크포인트 도달 후
> d 1988:18da           # Mode 1 소스 테이블 덤프
> d 1988:18f0           # Mode 2 소스 테이블 덤프
> d 1988:18c4           # 활성 테이블 덤프
```

### 방법 3: 메모리 덤프 분석

```bash
# DDMAIN.EXE에서 데이터 섹션 추출
dd if=DDMAIN.EXE bs=1 skip=$((0x18da)) count=22 | xxd
```
