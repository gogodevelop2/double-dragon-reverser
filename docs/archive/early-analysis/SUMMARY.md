# Double Dragon 바이너리 분석 최종 요약

## 완료된 작업

### ✅ 1. 바이너리 포맷 확인
- 모든 게임 파일(40개)이 **커스텀 LZW 변형** 압축 사용
- 시그니처: `0x1F 0x9D`
- 가변 비트 길이 (14-22 bits)

### ✅ 2. 압축 해제 루틴 발견
- **위치**: DDMAIN.EXE의 오프셋 0x6DE0
- **크기**: 약 512 bytes
- **타입**: x86 16비트 어셈블리 코드
- **파일**: `analysis/decompress_routine.bin`에 추출 완료

### ✅ 3. 분석 도구 개발
```
analysis/
├── analyze_binary.py           # 바이너리 구조 분석
├── decompress_lzw.py            # LZW 패턴 분석
├── extract_all.py               # 전체 파일 처리
├── reverse_decompress.py        # 리버스 엔지니어링
├── unicorn_decompress.py        # Unicorn 엔진 시도
├── decompress_routine.bin       # 추출된 압축 해제 루틴
├── BINARY_ANALYSIS_REPORT.md    # 상세 기술 보고서
├── DECOMPRESSION_FINDINGS.md    # 압축 해제 발견사항
└── FINAL_RECOMMENDATIONS.md     # 권장사항
```

## 발견한 내용

### 압축 포맷 상세

```
[오프셋 0x00] 0x1F        시그니처 바이트 1
[오프셋 0x01] 0x9D        시그니처 바이트 2
[오프셋 0x02] 플래그      비트 수 및 옵션
[오프셋 0x03] ...         압축 데이터
```

### 압축 해제 루틴 분석

**주요 어셈블리 코드**:
```assembly
0x6DE2: CMP  AX, 0x9D1F    ; 시그니처 확인
0x6DE5: JZ   decompress    ; 일치 시 압축 해제
0x6E63: SHL  AX, 1         ; 비트 시프트 연산
0x6EA7: ROL  BL, 1         ; 비트 로테이션
```

**사용된 메모리 주소**:
- 0x6538: 비트 버퍼
- 0x653A: 비트 카운터
- 0x6534: 출력 카운터

## 압축 해제 시도 결과

### ❌ 실패한 방법들

1. **unlzw3 라이브러리** - 표준 LZW와 호환 안 됨
2. **Unix uncompress** - 파일 포맷 불일치
3. **Unicorn 엔진 (부분 코드)** - 의존 함수 누락으로 실패

### 🤔 실패 원인

압축 해제 루틴이 **독립적이지 않음**:
- 다른 함수 호출 (CALL 명령어)
- 전역 변수/버퍼 사용
- DOS 인터럽트 사용 가능성

**해결책**: 전체 DDMAIN.EXE를 Unicorn으로 로드하거나, DOSBox 사용

## 실용적인 해결 방안

### 🏆 Option 1: DOSBox 메모리 덤프 (권장)

**방법**:
```bash
1. DOSBox-X 실행
2. 게임 로드 및 실행
3. Alt+Pause로 디버거 진입
4. 메모리 검색 및 덤프
```

**장점**:
- 100% 정확한 압축 해제 데이터
- 게임이 직접 처리
- 추가 코딩 불필요

**예상 시간**: 반나절

### ⚡ Option 2: 스크린샷 기반 (가장 빠름)

**방법**:
```bash
1. DOSBox로 게임 실행
2. 모든 스프라이트 스크린샷 (F5)
3. Aseprite로 스프라이트 시트 생성
```

**장점**:
- 바로 시작 가능
- 웹 최적화 가능
- 커스터마이징 자유

**예상 시간**: 2-3일

### 🔧 Option 3: 전체 EXE 에뮬레이션

**방법**:
```python
# DDMAIN.EXE 전체를 Unicorn으로 로드
# 파일 I/O 인터셉트
# 압축 해제 결과 캡처
```

**장점**:
- 자동화 가능
- 모든 파일 일괄 처리

**단점**:
- DOS 환경 구현 복잡
- 디버깅 어려움

**예상 시간**: 2-3일

## 배운 점

1. **커스텀 압축 = 시간 소모**
   - 1988년 게임은 표준 포맷 사용 안 함
   - 리버스 엔지니어링 시간 > 수동 작업 시간

2. **압축 해제 루틴 발견 성공**
   - DDMAIN.EXE에서 정확한 위치 찾음
   - 어셈블리 분석 가능
   - 하지만 독립 실행은 어려움

3. **실용적 접근이 최선**
   - 바이너리 분석보다 스크린샷이 빠름
   - 복각 목표에는 픽셀 단위 정확도 불필요
