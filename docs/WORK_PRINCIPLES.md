# 리버스 엔지니어링 작업 원칙

**프로젝트**: Double Dragon (1988) DOS Game
**최종 업데이트**: 2025-11-24

---

## ⚠️ 핵심 원칙 (절대 잊지 말 것)

### 1. 작은 프로그램은 실행 경로를 따라간다

> **"30년 전 72KB 프로그램은 실행 경로를 따라가면 모든 것을 알 수 있다"**

**잘못된 접근** ❌:
- 개별 함수만 분석
- 문자열 찾기, 메모리 주소 찾기부터 시작
- 변환 함수만 보기
- 복잡한 도구/자동화부터 시도

**올바른 접근** ✅:
- **entry point부터 시작**
- **실행 순서대로 함수 추적**
- **호출 체인 전체를 본다**
- **초기화 → 메인 루프 → 처리 함수 순서**

### 2. 이 프로그램의 특징

- 72KB 바이너리
- 118개 함수, 모두 디컴파일됨
- 전체 실행 경로를 추적할 수 있다
- 메모리에 통으로 올려서 시뮬레이션 가능
- **복잡하게 생각하지 마라**

### 3. 실행 경로 추적 방법

```
1. entry.c 읽기
2. 초기화 함수 찾기 (FUN_1000_0660, 069a, 06d4 등)
3. 각 함수가 호출하는 함수 순서대로 따라가기
4. LZW 압축 해제 → 다음 함수 → 다음 함수
5. 메인 루프에서 어떻게 사용하는지 확인
```

**절대 하지 말 것**:
- 개별 함수만 분석하고 "이게 뭘까?" 추측
- 문자열이나 주소 검색부터 시작
- 표준 라이브러리나 자동화 도구에 의존

---

## 📋 작업 방법

### 코드 분석

1. **디컴파일 코드를 한 줄씩 읽고 이해한다**
2. **이해한 내용을 간단한 C 프로그램으로 구현한다**
3. **실제 데이터에 적용해본다**
4. **안 되면 다시 디컴파일 코드로 돌아가서 한 줄씩 확인한다**

### 우선순위

1. ✅ 실행 경로 추적 (entry → init → main loop)
2. ✅ 호출 체인 따라가기 (함수 → 다음 함수)
3. ✅ 디컴파일 코드 한 줄씩 읽기
4. ❌ 자동화 스크립트 먼저 만들기
5. ❌ 복잡한 도구부터 시도

---

## 💡 교훈

### 실패한 접근들

1. **표준 LZW 라이브러리 사용**: 커스텀 LZW라서 실패
2. **문자열 검색**: 직접 참조가 없어서 실패
3. **개별 함수 분석**: 전체 흐름을 못 봐서 실패
4. **자동화 스크립트 먼저**: 이해 없이 만들어서 실패

### 성공한 접근

1. **실행 경로 추적**: entry → 초기화 → 메인 루프
2. **호출 체인 따라가기**: 함수 → 다음 함수 → 다음 함수
3. **디컴파일 코드 한 줄씩**: 정확히 이해
4. **간단한 것부터**: memcpy, 비트 연산 확인

### 앞으로의 원칙

1. 복잡하게 생각하지 마라
2. 실행 순서대로 따라가라
3. 디컴파일 코드를 신뢰하라
4. 한 줄씩 읽고 이해하라
5. 이해한 것을 간단히 구현하라
